# ห้องแกะนิยาย

เว็บสำหรับดึงตอนนิยายที่คุณเปิดอ่านอยู่ (เช่น ReadAWrite) แล้ววิเคราะห์ฟีล โทน จังหวะ และสไตล์การเขียน พร้อมเทียบร่างของคุณกับต้นฉบับว่าใกล้กันแค่ไหน

**ไม่ใช้ AI, ไม่ใช้คีย์, ไม่ส่งข้อความออกไปไหน** ทุกอย่างคำนวณในเบราว์เซอร์จากไฟล์เดียวคือ `index.html`

## เปิดใช้บน GitHub Pages

1. Push repo นี้ขึ้น GitHub
2. ไปที่ **Settings → Pages** แล้วตั้ง Source เป็น `Deploy from a branch`, `main` / `root`
3. เปิดลิงก์ `https://<username>.github.io/<repo>/`

## ใช้งาน

1. ลากปุ่ม **ดึงเข้าห้องแกะนิยาย** ไปไว้ที่แถบบุ๊กมาร์ก
2. เปิดตอนนิยาย ถ้าเว็บมีโหมดอ่านแบบ html ให้เลือกโหมดนั้น เพราะโหมด canvas เป็นรูปภาพและดึงข้อความไม่ได้ จากนั้นกดปุ่ม
3. แอปจะเปิดขึ้นและวิเคราะห์ให้ทันที
4. ในหัวข้อ **ลองแต่งแนวนี้** ให้วางร่างของคุณ แล้วกด **เทียบกับต้นฉบับ**

## สร้างตัวละครและพล็อต

แท็บ **สร้างตัวละครและพล็อต** ใช้วางโครงนิยายของคุณเอง

1. **ตัวละคร:** กรอกรายละเอียด 5 หมวด คือ ตัวตน, รูปลักษณ์, จิตใจ (นิสัย ข้อเสีย สิ่งที่อยากได้ สิ่งที่กลัว), ภูมิหลัง (ปมในอดีต ความลับ) และอื่นๆ ทุกช่องมีปุ่ม **สุ่ม** เพิ่มตัวละครได้หลายตัว และกำหนดบทบาทได้ (ตัวเอก, คู่, ตัวร้าย ฯลฯ)
2. **พล็อต:** เลือกแนวเรื่อง, โครงเรื่อง (สามองก์, การเดินทางของฮีโร่, คิโชเท็นเค็ตสึ), ความขัดแย้งหลัก, ตอนจบ, จำนวนตอน และฉาก ปุ่ม **ใช้แนวจากผลวิเคราะห์** จะดึงแนวจากนิยายที่เพิ่งแกะมาใช้
3. กด **สร้างพล็อต** ระบบจะเติมช่องที่ว่างให้ แล้วสร้างแก่นเรื่อง, โปรไฟล์ตัวละคร, ความสัมพันธ์ และโครงเรื่องแยกตามตอน
4. กด **สุ่มเหตุการณ์ใหม่** เพื่อลองเหตุการณ์ชุดอื่น หรือกด **คัดลอกเป็นข้อความ** เพื่อนำไปใช้ต่อ

ระบบสร้างจากเทมเพลตเหตุการณ์ของแต่ละแนว (`PLOTS`, `BEATS`, `ENDINGS`) ผสมกับรายละเอียดตัวละครที่กรอก ไม่ใช้ AI ถ้าอยากได้เหตุการณ์หลากหลายขึ้น ให้เพิ่มประโยคในรายการเหล่านั้น ข้อมูลตัวละครจะบันทึกไว้ในเบราว์เซอร์ที่ใช้อยู่

### โหมดสร้างตามกฎ (Procedural)

ทั้งหมดคำนวณในเครื่อง ไม่มีโค้ดเรียก AI หรือเครือข่าย ใช้ออฟไลน์ได้ (ฟอนต์จาก Google Fonts ไม่โหลดก็ยังใช้งานได้)

- **นิสัยกำหนดการกระทำ:** นิสัยและข้อเสียแต่ละอย่างผูกกับวิธีรับมือ (`LEAN` เช่น เผชิญหน้า เก็บตัว สืบก่อน) เหตุการณ์ "ทางเลือก" มาจากนิสัยตัวเอก และไคลแมกซ์คือจุดที่ตัวเอกเลือกสวนข้อเสียของตัวเอง ซึ่งเรื่องอธิบายเหตุผลไว้
- **ความขัดแย้งหลัก:** หาจากสิ่งที่ตัวละครต้องการชนกัน นิสัยที่ปะทะกัน (`CLASH`) ความลับ และตัวร้าย ถ้ามีตัวละครตัวเดียวจะใช้ความขัดแย้งภายใน (สิ่งที่อยากได้กับสิ่งที่กลัว)
- **เหตุและผล:** ทุกเหตุการณ์บอกว่าเกิดเพราะอะไร ต่อจากเหตุการณ์ไหน และทำให้อะไรเปลี่ยน
- **จุดหักมุม 10 แบบ** (`TWISTS`) แต่ละแบบบอกว่าคนอ่านเชื่ออะไร ตัวละครเชื่ออะไร ความจริงคืออะไร เบาะแสที่ปูไว้ เหตุผลที่ไม่มีใครรู้ก่อน และเดิมพันที่เปลี่ยน ระบบจะไม่ให้ตัวละครนิสัยซื่อสัตย์เป็นคนหักหลัง และไม่ใช้แบบเดิมซ้ำกับครั้งก่อน แนวลึกลับจะมีเบาะแสหลอกด้วย
- **ตรวจและซ่อม:** กฎใน `RULES` ตรวจเหตุการณ์ที่ไม่มีเหตุ ข้อมูลหรือทักษะที่โผล่มาก่อนถูกปู ตัวละครที่หายไปแล้วโผล่มา เบาะแสไม่พอหรือวางหลังเฉลย จุดหักมุมที่ขัดประวัติ การกระทำที่ไม่ตรงนิสัย ตอนจบที่ไม่ตอบความขัดแย้ง เหตุการณ์ซ้ำ และคำต้องห้าม ถ้าเจอปัญหา ระบบจะแก้เฉพาะเหตุการณ์นั้น ไม่สร้างใหม่ทั้งเรื่อง
- **ความใหม่:** เก็บลายนิ้วมือของพล็อต 30 เรื่องล่าสุด แล้ววัดว่าองค์ประกอบซ้ำกันกี่เปอร์เซ็นต์ ใช้จับการซ้ำของโครงเท่านั้น ไม่ได้รับประกันว่าเรื่องจะแปลกใหม่
- **ตัวเลือก:** จำนวนพล็อตที่ให้เลือก (1/3/5), ความซับซ้อน, ความเข้มของการตรวจ, แบบจุดหักมุม, สิ่งที่ห้ามมี และ **เลขสุ่ม (seed)** ถ้าใส่ seed เดิมกับข้อมูลเดิม จะได้พล็อตเดิม
- แก้ข้อความแต่ละเหตุการณ์ได้โดยตรง หรือกด **สุ่มใหม่เฉพาะตอนนี้** พล็อตล่าสุดบันทึกไว้ในเบราว์เซอร์พร้อมข้อมูลตัวละคร

ผลตรวจเป็นการนับตามกฎ ไม่ใช่คะแนนคุณภาพงานเขียน

## วิเคราะห์อย่างไร

| ด้าน | วิธีวัด |
|---|---|
| ฟีล / แนวเรื่อง | นับคำอารมณ์จากรายการคำในแต่ละหมวด (`FEELS`) ต่อ 1,000 ตัวอักษร |
| มุมมองการเล่า | นับ ผม/ฉัน เทียบกับ เขา/เธอ ในส่วนบรรยาย (ไม่นับในเครื่องหมายคำพูด) |
| บทพูด | สัดส่วนตัวอักษรที่อยู่ในเครื่องหมายคำพูด |
| ความยาววลี / ย่อหน้า | ตัวอักษรเฉลี่ยต่อช่วงที่คั่นด้วยการเว้นวรรค และต่อย่อหน้า |
| ผัสสะ | นับคำเกี่ยวกับแสง เสียง กลิ่น อากาศ |
| คำที่วนซ้ำ | ตัดคำภาษาไทยด้วย `Intl.Segmenter` แล้วนับคำที่เจอบ่อย ชื่อที่ถูกตัดแยกจะถูกต่อกลับ |
| เนื้อเรื่องย่อ | เลือก 3 ประโยคที่มีคำสำคัญของตอนมากที่สุด เรียงตามลำดับเรื่อง |
| ตัวละคร | คำที่วนซ้ำซึ่งตามด้วยการกระทำ (เดิน มอง พูด ฯลฯ) หรืออยู่ในฉากที่มีบทพูด แล้วอ่านนิสัยจากคำรอบชื่อ (`TRAITS`) |
| อารมณ์ไล่ตามตอน | แบ่งตอนเป็น 6 ช่วง แล้ววัดฟีลทีละช่วง เพื่อหาจุดพีค |
| ระดับภาษา | นับหางเสียง คำหยาบ และคำแบบวรรณกรรม |
| คำปฏิเสธ | คำที่มี ไม่/ไม่ได้/ไร้ นำหน้าจะไม่ถูกนับ |
| ความใกล้เคียง | เทียบแต่ละด้านของร่างกับต้นฉบับ แล้วเฉลี่ยเป็นเปอร์เซ็นต์ |

ถ้าระบบจับแนวหรือนิสัยผิด ให้เพิ่มคำในรายการ `FEELS` หรือ `TRAITS` ที่ส่วนบนของสคริปต์

## ข้อจำกัด

- เรื่องย่อเป็นประโยคที่ดึงมาจากต้นฉบับ ไม่ได้เรียบเรียงใหม่ ส่วนนิสัยตัวละครอ่านจากคำรอบชื่อ ไม่ได้เข้าใจความหมาย ตัวละครที่ถูกเรียกแค่ "เขา/เธอ" จะหาไม่เจอ
- ระบบไม่เขียนเนื้อหาให้
- ปุ่มดึงได้เฉพาะตอนที่คุณเปิดอ่านได้อยู่แล้ว ใช้เพื่อศึกษาส่วนตัว และอย่าเผยแพร่เนื้อหาของผู้เขียนคนอื่น

## ตรวจโค้ด

รัน `node test.js` (Node 18 ขึ้นไป ไม่ต้องติดตั้งอะไรเพิ่ม) เพื่อเช็กว่าตัววิเคราะห์และตัวสร้างพล็อตยังทำงานถูกต้อง รวมถึงการสร้างซ้ำได้จาก seed, การไม่เรียกเครือข่าย, เหตุและผล, เบาะแส และการตรวจจับข้อขัดแย้ง

## คลัง ReadAWrite (local import)

แท็บ **คลัง ReadAWrite** รับ URL เพื่อเปิดหน้าต้นทาง และเก็บตอนที่ผู้ใช้ดึงด้วย bookmarklet ไว้ใน browser localStorage สามารถวิเคราะห์ตอนที่เก็บไว้ เปิด URL ต้นทาง ลบตอน ส่งออก JSON และนำ JSON สำรองกลับเข้าคลังได้ ข้อมูลทำงานในเบราว์เซอร์ ไม่ส่งต้นฉบับไปยัง AI API

### รูปแบบนำเข้าและตรวจวินิจฉัย

- Bookmarklet ใช้ข้อความที่เลือกไว้หากเลือกมาพอสมควร หรือสแกนบริเวณข้อความที่มองเห็นได้ โดยพิจารณา `article`, `main`, `role=main`, กลุ่ม `chapter/reader/content` และกลุ่มย่อหน้า ไม่พึ่งแท็ก `p` เพียงอย่างเดียว
- ช่อง URL รับลิงก์เต็ม, โดเมนที่ไม่มี `https://`, URL ที่คัดจาก Markdown, HTML entity เช่น `&amp;`, และ URL ทั้งเส้นที่ถูก percent-encode แบบ `https%3A%2F%2F...` โดยไม่แกะ percent-encoding ปกติใน path/query ทิ้ง ตรวจโดเมนให้ตรงกับ `readawrite.com` และเปิดด้วย HTTPS
- สามารถเลือกไฟล์หน้าเว็บที่บันทึกไว้เป็น `.html`, `.htm`, `.xhtml` หรือ MHTML (`.mhtml`, `.mht` แบบเว็บไฟล์เดียวจากเบราว์เซอร์) ระบบจะแกะ MIME/quoted-printable/Base64 ของส่วน `text/html` มาประมวลผลในเบราว์เซอร์ แล้วดึงเฉพาะข้อความใน DOM และพยายามเลือกส่วน `article/main/chapter/reader/content` พร้อมอ่านชื่อหน้าและ canonical/content URL
- ถ้าตั้งใจลากเลือกเพียงบางย่อหน้า bookmarklet รับข้อความที่เลือกตั้งแต่ 80 ตัวอักษรขึ้นไปได้แล้ว ส่วนการสแกนอัตโนมัติจะคัดตัวเลือกจากบริเวณเนื้อหาที่มองเห็นได้และเก็บชื่อ selector ไว้ตรวจย้อนหลัง
- ระบบเก็บวิธีนำเข้า ตัวเลือกพื้นที่ จำนวนตัวอักษร และสัญญาณอักขระพิเศษไว้ในข้อมูลวินิจฉัย เพื่อช่วยดูว่าคัดมาได้สั้นเกินไปหรือเลือกผิดบริเวณ
- การนำเข้าซ้ำจาก URL เดิมจะรวมเฉพาะข้อความซ้ำ/ช่วงซ้อนที่ตรวจได้ชัด หากไม่มีช่วงซ้อนจะเก็บต่อท้าย และเก็บจำนวนครั้งที่นำเข้าให้ตรวจย้อนกลับได้
- รายการที่มีอักขระอ่านไม่ได้หรือรูปแบบข้อความน่าสงสัยจะถูกเก็บเป็น **รอตรวจ** แทนการทิ้งข้อมูล แต่จะไม่เปิดให้วิเคราะห์อัตโนมัติจนกว่าจะมีข้อความที่อ่านได้ รายการเหล่านี้ส่งออกไปกับไฟล์ JSON สำรองได้
- ปุ่ม **นำเข้า JSON** ใช้คืนค่าคลังจากไฟล์ที่ NovelLens ส่งออก ระบบตรวจชนิดรายการ ขนาด และ URL ก่อนรวมรายการที่ตรงกัน รายการอักขระผิดปกติจะถูกกักเป็นรอตรวจเช่นเดิม
- หากหน้าเว็บแสดงเนื้อหาเป็น canvas/ภาพ หรืออ่านข้อความจาก DOM ไม่ได้ ให้ใช้ภาพหน้าจอที่คุณมีสิทธิ์ใช้งานแล้วนำไป OCR ในแท็บแกะนิยาย และตรวจแก้กับภาพต้นฉบับก่อนวิเคราะห์

**ข้อจำกัดของ GitHub Pages:** เว็บสแตติกไม่สามารถอ่านรายการตอนหรือเนื้อหาจาก ReadAWrite ข้ามโดเมนได้เอง ดังนั้น URL อย่างเดียวไม่ได้ทำให้ระบบนำเข้าทุกตอนอัตโนมัติ ต้องเปิดแต่ละหน้าตอนที่คุณมีสิทธิ์อ่านแล้วกด bookmarklet “ดึงเข้าห้องแกะนิยาย” เพื่อเก็บตอนนั้น การนำเข้า HTML เป็นการอ่านไฟล์ที่ผู้ใช้บันทึกเอง ไม่ได้เชื่อมต่อเพื่อดึงข้อมูลจากเว็บอัตโนมัติ URL ที่มี `%` จะถูกจัดการในฐานะรูปแบบ URL แต่เนื้อหาที่ถูกแมปเป็น glyph ของฟอนต์เฉพาะจะยังคงอยู่ในสถานะรอตรวจ ไม่ถอดรหัสระบบป้องกันการคัดลอก

ใช้เพื่อนำเข้างานของคุณเองหรือผลงานที่ได้รับอนุญาตเท่านั้น

## ห้องวางแผนเขียน (Writer's Room)

แท็บ **ห้องวางแผนเขียน** เป็นพื้นที่เขียนงานแบบ offline-first ที่เก็บข้อมูลไว้ใน localStorage ของเบราว์เซอร์เครื่องนี้

### คลังตัวละครและการผสม

- เก็บแฟ้มตัวละครแยกจากตัวสร้างพล็อตเดิม แก้ชื่อ บทบาท บุคลิก นิสัย จุดแข็ง/จุดบอด แรงปรารถนา ความกลัว ความลับ ภูมิหลัง วิธีพูด ความสัมพันธ์ และ URL อ้างอิงได้
- ดึงตัวละครจากตัวสร้างเดิมโดยไม่แทนที่ตัวละครที่มีชื่อซ้ำ ส่งออกคลังเป็น JSON และนำเข้าคลัง JSON กลับมาใช้ในเบราว์เซอร์อื่นได้
- เลือกตัวละคร 2–4 ตัวมาผสม ปรับน้ำหนักอิทธิพล และแก้โปรไฟล์ผลลัพธ์ก่อนบันทึก ตัวช่วยยังสร้างเมล็ดพล็อตจากแรงปรารถนาที่ขัดกัน แต่ผลทุกช่องแก้ไขได้

### โต๊ะอ้างอิงบุคคล/ตัวละครต้นแบบ

- ค้นสรุปจาก Wikipedia ภาษาไทยและอังกฤษผ่าน MediaWiki Action API โดยใช้ anonymous CORS query และมีลิงก์เปิดต้นทางให้ตรวจสอบ
- วาง URL หลายเว็บไซต์ได้ในครั้งเดียวและเพิ่มบันทึก/ข้อความสรุปที่ผู้ใช้ตรวจแล้ว เว็บไซต์ที่ไม่อนุญาตให้เรียกจาก JavaScript ของหน้าเว็บจะไม่ถูกดึงเนื้อหาอัตโนมัติ
- วางลิงก์หลายอันแล้วกด **สร้างตัวละครจากลิงก์เหล่านี้เลย** (ครั้งละไม่เกิน 12 ลิงก์) ระบบสร้างแฟ้มตัวละครลงคลังทันที ลิงก์ Wikipedia และเว็บวิกิแบบ MediaWiki (เช่น Fandom) อ่านได้ผ่าน API ส่วนเว็บอื่นอ่านได้เฉพาะที่อนุญาต CORS ถ้าอ่านไม่ได้จะสร้างแฟ้มเปล่าพร้อมลิงก์ต้นทางไว้ให้เติมเอง (ข้อความในช่อง "ข้อความสรุป/บันทึก" จะใช้เป็นภูมิหลังให้) ตัวละครที่ได้เก็บแค่นิสัยที่จับได้กับสรุปสั้นๆ และลิงก์ต้นทาง ไม่คัดลอกเนื้อหาทั้งหน้า และข้ามลิงก์ที่มีตัวละครอยู่แล้ว
- เปลี่ยนแหล่งอ้างอิงเป็นแฟ้มตัวละครที่แก้ไขได้ ระบบจงใจเว้นชื่อใหม่ไว้ให้ตั้งเอง และมีคำแนะนำให้ดัดแปลงเป็นตัวละครสมมติแทนการใช้บุคคลจริงตรง ๆ
- ใช้ข้อมูลสาธารณะที่เกี่ยวข้องกับงานเขียนเท่านั้น หลีกเลี่ยงข้อมูลส่วนตัวหรือข้อมูลอ่อนไหวของบุคคลทั่วไป

### Story Planner และกราฟเรื่อง

- กำหนดให้เรื่องจบในเล่มเดียวหรือเป็นซีรีส์ จำนวนตอน/บท วันเริ่ม วันส่ง จำนวนคำ เป้าหมายต่อบท แนวเรื่อง คำถามหลัก ธีม ตอนจบ มุมมอง และตัวละครที่ร่วมเรื่อง
- ตั้ง mood ของเรื่องหลายด้าน รวมทั้งความเศร้า ตลกร้าย แรงกดดัน การเสียดสีสังคม และความอบอุ่น เลือกคุณลักษณะการเล่าที่ต้องการ และใช้ preset เชิงคุณลักษณะระดับสูงเป็นจุดเริ่มต้น
- วางแผนรายตอนพร้อมเป้าหมาย ฉาก ความขัดแย้ง เบาะแส จุดหักมุม hook และบันทึกการเชื่อมกับตอนอื่น แก้ไขทุกช่องได้โดยไม่ต้องสร้างใหม่ทั้งหมด
- กราฟ SVG แสดงแรงกดดันรายตอน จุด twist และรายการเตือนความต่อเนื่อง เช่น twist ที่ยังไม่มีเบาะแส ตอนที่ขาดฉาก/ความขัดแย้ง การเปลี่ยนชุดตัวละครแบบไม่มีบันทึก Mood ที่ซ้ำตลอดเรื่อง ตัวละครที่เลือกไว้แต่ยังไม่ปรากฏในตอน และแรงกดดันสูงสุดที่เกิดเร็วเกินไป คำเตือนเป็น heuristic ให้ผู้เขียนตรวจ ไม่ใช่ข้อผิดพลาดที่ต้องแก้ทุกข้อ
- **กระดานเบาะแสและจุดหักมุม** แสดง clue/twist รายตอนพร้อมตัวนับและตำแหน่งเบาะแสก่อนหน้า ช่วยชี้จุดที่ยังไม่พบการปูข้อมูลหรือเบาะแสที่อาจต้องมีผลภายหลัง โดยไม่อ้างว่าเชื่อม clue กับ twist ได้ถูกต้องอัตโนมัติ ผู้เขียนเป็นผู้ตรวจความสัมพันธ์จริงเอง
- คะแนนความพร้อมเป็น checklist ของข้อมูลที่กรอก ไม่ใช่คำรับรองคุณภาพทางวรรณกรรมหรือการทำนายที่แม่นยำแน่นอน

### วิเคราะห์ตัวอย่างลายมือการเล่า

ผู้ใช้สามารถวางตัวอย่างข้อความที่ตนเป็นเจ้าของหรือมีสิทธิ์ใช้ แล้วให้ระบบวัดความยาวประโยค/ย่อหน้า สัดส่วนบทสนทนา คำถาม เครื่องหมายอุทาน คำซ้ำ และสัญญาณคำที่สื่อโทน ระบบคำนวณในเบราว์เซอร์และแนะนำคุณลักษณะรูปแบบที่อาจใช้กับ Planner ต่อได้ ตัวเลขเป็นเพียง heuristic จากตัวอย่าง ไม่สามารถยืนยันตัวตนผู้เขียนหรือสรุปสไตล์จากหนังสือทั้งเล่มได้

### ปฏิทินเขียนและวันส่ง

- ตั้งวันเริ่ม วันเสร็จ และวันเขียนในสัปดาห์ แล้วสร้างตัวอย่างตารางรายวันพร้อมคำเป้าหมายและจำนวนหน้าโดยประมาณ
- ตารางจะยังไม่ถูกนำไปใช้จนกว่าผู้ใช้จะตรวจภาระงานและกด **ยืนยันและบันทึกตาราง** เอง หากจำนวนคำต่อวันสูง ระบบจะเตือนให้พิจารณาลดเป้าหมายหรือขยายเวลา
- ปฏิทินเก็บสถานะงานที่เสร็จ จำนวนคำจริง และบันทึกรายวัน ส่งออกโปรเจกต์เป็น JSON หรือ Markdown ได้

**ข้อจำกัด:** Writer's Room รุ่นนี้ไม่ใช้โมเดล AI และไม่ได้อ่านทุกเว็บไซต์โดยอัตโนมัติ ส่วนการเชื่อมโครงเรื่องและการวัดลายมือใช้กฎกับข้อมูลที่ผู้ใช้กรอก คุณควรตรวจความสมเหตุสมผลและแก้ร่างเองเสมอ

## ตรวจคุณภาพข้อความและความน่าเชื่อถือของผลวิเคราะห์

ตัววิเคราะห์ตรวจจับอักขระ Unicode Private Use Area (PUA), อักขระทดแทน, control characters และ zero-width ก่อนประมวลผล หากตรวจพบรูปแบบที่มีแนวโน้มว่าอ่านไม่ได้ จะหยุดการวิเคราะห์และเก็บรายการไว้ในคลังสถานะ **รอตรวจ** พร้อมแสดงจำนวนและสัดส่วนที่พบ ไม่ลบข้อความดิบออกจากคลัง อย่างไรก็ตาม ตัวเลขเปอร์เซ็นต์คือสัดส่วนของอักขระที่ตรวจพบ ไม่ใช่ความมั่นใจในการถอดรหัส

ผู้ใช้สามารถเปิดไฟล์ `.txt` หรือ `.md` ที่เข้าถึงได้โดยชอบด้วยสิทธิ์ หรือวางข้อความสะอาดลงในช่องต้นฉบับได้ ระบบไม่พยายามถอดรหัสฟอนต์เฉพาะหรือหลบกลไกป้องกันการคัดลอกของเว็บไซต์

ผลแนวเรื่องจะแสดงคำ/วลีที่ใช้เป็นหลักฐานและระดับความชัดเจนแบบเชิงกฎ โดยไม่อ้างว่าเป็นความเข้าใจเชิงความหมายระดับมนุษย์ ส่วนรายชื่อตัวละครเป็นเพียงผู้สมัครที่ตรวจทานได้ เพราะรุ่นนี้ไม่ใช้โมเดลภาษาและอนุมานจากรูปแบบการปรากฏของคำ
