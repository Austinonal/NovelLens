# ห้องแกะนิยาย

เว็บสำหรับดึงตอนนิยายที่คุณเปิดอ่านอยู่ (เช่น ReadAWrite) แล้ววิเคราะห์ฟีล โทน จังหวะ และสไตล์การเขียน พร้อมเทียบร่างของคุณกับต้นฉบับว่าใกล้กันแค่ไหน

**ไม่ใช้ AI, ไม่ใช้คีย์, ไม่ส่งข้อความออกไปไหน** ทุกอย่างคำนวณในเบราว์เซอร์จากไฟล์เดียวคือ `index.html`

## เปิดใช้บน GitHub Pages

1. Push repo นี้ขึ้น GitHub
2. ไปที่ **Settings → Pages** แล้วตั้ง Source เป็น `Deploy from a branch`, `main` / `root`
3. เปิดลิงก์ `https://<username>.github.io/<repo>/`

## ใช้งาน

1. ลากปุ่ม **ดึงเข้าห้องแกะนิยาย** ไปไว้ที่แถบบุ๊กมาร์ก
2. เปิดตอนนิยาย ถ้าเว็บมีโหมดอ่านแบบ html ให้เลือกโหมดนั้น เพราะโหมด canvas เป็นรูปภาพและดึงข้อความไม่ได้ จากนั้นกดปุ่ม
3. แอปจะเปิดขึ้นและวิเคราะห์ให้ทันที
4. ในหัวข้อ **ลองแต่งแนวนี้** ให้วางร่างของคุณ แล้วกด **เทียบกับต้นฉบับ**

## สร้างตัวละครและพล็อต

แท็บ **สร้างตัวละครและพล็อต** ใช้วางโครงนิยายของคุณเอง

1. **ตัวละคร:** กรอกรายละเอียด 5 หมวด คือ ตัวตน, รูปลักษณ์, จิตใจ (นิสัย ข้อเสีย สิ่งที่อยากได้ สิ่งที่กลัว), ภูมิหลัง (ปมในอดีต ความลับ) และอื่นๆ ทุกช่องมีปุ่ม **สุ่ม** เพิ่มตัวละครได้หลายตัว และกำหนดบทบาทได้ (ตัวเอก, คู่, ตัวร้าย ฯลฯ)
2. **พล็อต:** เลือกแนวเรื่อง, โครงเรื่อง (สามองก์, การเดินทางของฮีโร่, คิโชเท็นเค็ตสึ), ความขัดแย้งหลัก, ตอนจบ, จำนวนตอน และฉาก ปุ่ม **ใช้แนวจากผลวิเคราะห์** จะดึงแนวจากนิยายที่เพิ่งแกะมาใช้
3. กด **สร้างพล็อต** ระบบจะเติมช่องที่ว่างให้ แล้วสร้างแก่นเรื่อง, โปรไฟล์ตัวละคร, ความสัมพันธ์ และโครงเรื่องแยกตามตอน
4. กด **สุ่มเหตุการณ์ใหม่** เพื่อลองเหตุการณ์ชุดอื่น หรือกด **คัดลอกเป็นข้อความ** เพื่อนำไปใช้ต่อ

ระบบสร้างจากเทมเพลตเหตุการณ์ของแต่ละแนว (`PLOTS`, `BEATS`, `ENDINGS`) ผสมกับรายละเอียดตัวละครที่กรอก ไม่ใช้ AI ถ้าอยากได้เหตุการณ์หลากหลายขึ้น ให้เพิ่มประโยคในรายการเหล่านั้น ข้อมูลตัวละครจะบันทึกไว้ในเบราว์เซอร์ที่ใช้อยู่

### โหมดสร้างตามกฎ (Procedural)

ทั้งหมดคำนวณในเครื่อง ไม่มีโค้ดเรียก AI หรือเครือข่าย ใช้ออฟไลน์ได้ (ฟอนต์จาก Google Fonts ไม่โหลดก็ยังใช้งานได้)

- **นิสัยกำหนดการกระทำ:** นิสัยและข้อเสียแต่ละอย่างผูกกับวิธีรับมือ (`LEAN` เช่น เผชิญหน้า เก็บตัว สืบก่อน) เหตุการณ์ "ทางเลือก" มาจากนิสัยตัวเอก และไคลแมกซ์คือจุดที่ตัวเอกเลือกสวนข้อเสียของตัวเอง ซึ่งเรื่องอธิบายเหตุผลไว้
- **ความขัดแย้งหลัก:** หาจากสิ่งที่ตัวละครต้องการชนกัน นิสัยที่ปะทะกัน (`CLASH`) ความลับ และตัวร้าย ถ้ามีตัวละครตัวเดียวจะใช้ความขัดแย้งภายใน (สิ่งที่อยากได้กับสิ่งที่กลัว)
- **เหตุและผล:** ทุกเหตุการณ์บอกว่าเกิดเพราะอะไร ต่อจากเหตุการณ์ไหน และทำให้อะไรเปลี่ยน
- **จุดหักมุม 10 แบบ** (`TWISTS`) แต่ละแบบบอกว่าคนอ่านเชื่ออะไร ตัวละครเชื่ออะไร ความจริงคืออะไร เบาะแสที่ปูไว้ เหตุผลที่ไม่มีใครรู้ก่อน และเดิมพันที่เปลี่ยน ระบบจะไม่ให้ตัวละครนิสัยซื่อสัตย์เป็นคนหักหลัง และไม่ใช้แบบเดิมซ้ำกับครั้งก่อน แนวลึกลับจะมีเบาะแสหลอกด้วย
- **ตรวจและซ่อม:** กฎใน `RULES` ตรวจเหตุการณ์ที่ไม่มีเหตุ ข้อมูลหรือทักษะที่โผล่มาก่อนถูกปู ตัวละครที่หายไปแล้วโผล่มา เบาะแสไม่พอหรือวางหลังเฉลย จุดหักมุมที่ขัดประวัติ การกระทำที่ไม่ตรงนิสัย ตอนจบที่ไม่ตอบความขัดแย้ง เหตุการณ์ซ้ำ และคำต้องห้าม ถ้าเจอปัญหา ระบบจะแก้เฉพาะเหตุการณ์นั้น ไม่สร้างใหม่ทั้งเรื่อง
- **ความใหม่:** เก็บลายนิ้วมือของพล็อต 30 เรื่องล่าสุด แล้ววัดว่าองค์ประกอบซ้ำกันกี่เปอร์เซ็นต์ ใช้จับการซ้ำของโครงเท่านั้น ไม่ได้รับประกันว่าเรื่องจะแปลกใหม่
- **ตัวเลือก:** จำนวนพล็อตที่ให้เลือก (1/3/5), ความซับซ้อน, ความเข้มของการตรวจ, แบบจุดหักมุม, สิ่งที่ห้ามมี และ **เลขสุ่ม (seed)** ถ้าใส่ seed เดิมกับข้อมูลเดิม จะได้พล็อตเดิม
- แก้ข้อความแต่ละเหตุการณ์ได้โดยตรง หรือกด **สุ่มใหม่เฉพาะตอนนี้** พล็อตล่าสุดบันทึกไว้ในเบราว์เซอร์พร้อมข้อมูลตัวละคร

ผลตรวจเป็นการนับตามกฎ ไม่ใช่คะแนนคุณภาพงานเขียน

## วิเคราะห์อย่างไร

| ด้าน | วิธีวัด |
|---|---|
| ฟีล / แนวเรื่อง | นับคำอารมณ์จากรายการคำในแต่ละหมวด (`FEELS`) ต่อ 1,000 ตัวอักษร |
| มุมมองการเล่า | นับ ผม/ฉัน เทียบกับ เขา/เธอ ในส่วนบรรยาย (ไม่นับในเครื่องหมายคำพูด) |
| บทพูด | สัดส่วนตัวอักษรที่อยู่ในเครื่องหมายคำพูด |
| ความยาววลี / ย่อหน้า | ตัวอักษรเฉลี่ยต่อช่วงที่คั่นด้วยการเว้นวรรค และต่อย่อหน้า |
| ผัสสะ | นับคำเกี่ยวกับแสง เสียง กลิ่น อากาศ |
| คำที่วนซ้ำ | ตัดคำภาษาไทยด้วย `Intl.Segmenter` แล้วนับคำที่เจอบ่อย ชื่อที่ถูกตัดแยกจะถูกต่อกลับ |
| เนื้อเรื่องย่อ | เลือก 3 ประโยคที่มีคำสำคัญของตอนมากที่สุด เรียงตามลำดับเรื่อง |
| ตัวละคร | คำที่วนซ้ำซึ่งตามด้วยการกระทำ (เดิน มอง พูด ฯลฯ) หรืออยู่ในฉากที่มีบทพูด แล้วอ่านนิสัยจากคำรอบชื่อ (`TRAITS`) |
| อารมณ์ไล่ตามตอน | แบ่งตอนเป็น 6 ช่วง แล้ววัดฟีลทีละช่วง เพื่อหาจุดพีค |
| ระดับภาษา | นับหางเสียง คำหยาบ และคำแบบวรรณกรรม |
| คำปฏิเสธ | คำที่มี ไม่/ไม่ได้/ไร้ นำหน้าจะไม่ถูกนับ |
| ความใกล้เคียง | เทียบแต่ละด้านของร่างกับต้นฉบับ แล้วเฉลี่ยเป็นเปอร์เซ็นต์ |

ถ้าระบบจับแนวหรือนิสัยผิด ให้เพิ่มคำในรายการ `FEELS` หรือ `TRAITS` ที่ส่วนบนของสคริปต์

## ข้อจำกัด

- เรื่องย่อเป็นประโยคที่ดึงมาจากต้นฉบับ ไม่ได้เรียบเรียงใหม่ ส่วนนิสัยตัวละครอ่านจากคำรอบชื่อ ไม่ได้เข้าใจความหมาย ตัวละครที่ถูกเรียกแค่ "เขา/เธอ" จะหาไม่เจอ
- ระบบไม่เขียนเนื้อหาให้
- ปุ่มดึงได้เฉพาะตอนที่คุณเปิดอ่านได้อยู่แล้ว ใช้เพื่อศึกษาส่วนตัว และอย่าเผยแพร่เนื้อหาของผู้เขียนคนอื่น

## ตรวจโค้ด

รัน `node test.js` (Node 18 ขึ้นไป ไม่ต้องติดตั้งอะไรเพิ่ม) เพื่อเช็กว่าตัววิเคราะห์และตัวสร้างพล็อตยังทำงานถูกต้อง รวมถึงการสร้างซ้ำได้จาก seed, การไม่เรียกเครือข่าย, เหตุและผล, เบาะแส และการตรวจจับข้อขัดแย้ง

## คลัง ReadAWrite (local import)

แท็บ **คลัง ReadAWrite** รับ URL เพื่อเปิดหน้าต้นทาง และเก็บตอนที่ผู้ใช้ดึงด้วย bookmarklet ไว้ใน browser localStorage สามารถวิเคราะห์ตอนที่เก็บไว้ เปิด URL ต้นทาง ลบตอน หรือส่งออกคลังเป็น JSON ได้ ข้อมูลที่นำเข้าไม่ถูกส่งไปยัง AI API

**ข้อจำกัดของ GitHub Pages:** เว็บสแตติกไม่สามารถอ่านรายการตอนหรือเนื้อหาจาก ReadAWrite โดยตรงข้ามโดเมนได้ ดังนั้น URL อย่างเดียวไม่ได้ทำให้ระบบนำเข้าทุกตอนอัตโนมัติ ต้องเปิดแต่ละหน้าตอนที่มีสิทธิ์อ่านแล้วกด bookmarklet “ดึงเข้าห้องแกะนิยาย” เพื่อเก็บตอนนั้น การตรวจ URL ใน UI ตรวจได้เฉพาะรูปแบบโดเมน ไม่ใช่การยืนยันชื่อเรื่อง/ตอนจากเนื้อหาหน้าเว็บ การนำเข้าเต็มเรื่องแบบอัตโนมัติต้องใช้ browser extension หรือแอป/บริการ local ที่ควบคุมเบราว์เซอร์และมีการทดสอบแยกต่างหาก

ใช้เพื่อนำเข้างานของคุณเองหรือผลงานที่ได้รับอนุญาตเท่านั้น

## ตรวจคุณภาพข้อความและความน่าเชื่อถือของผลวิเคราะห์

ตัววิเคราะห์ตรวจจับอักขระใน Unicode Private Use Area และอักขระเสียหายก่อนประมวลผล หากข้อความมีลักษณะเป็นตัวแทน glyph จากฟอนต์พิเศษ จะหยุดการวิเคราะห์และไม่บันทึกข้อความนั้นเข้าคลัง เพื่อไม่ให้ข้อความที่อ่านไม่ออกกลายเป็นพล็อตหรือตัวละครที่แต่งขึ้นจากการเดาคำ

ผู้ใช้สามารถเปิดไฟล์ `.txt` หรือ `.md` ที่เข้าถึงได้โดยชอบด้วยสิทธิ์ หรือวางข้อความสะอาดลงในช่องต้นฉบับได้ ระบบไม่พยายามถอดรหัสฟอนต์หรือหลบกลไกป้องกันการคัดลอกของเว็บไซต์

ผลแนวเรื่องจะแสดงคำ/วลีที่ใช้เป็นหลักฐานและระดับความชัดเจนแบบเชิงกฎ โดยไม่อ้างว่าเป็นความเข้าใจเชิงความหมายระดับมนุษย์ ส่วนรายชื่อตัวละครเป็นเพียงผู้สมัครที่ตรวจทานได้ เพราะรุ่นนี้ไม่ใช้โมเดลภาษาและอนุมานจากรูปแบบการปรากฏของคำ
